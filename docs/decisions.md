# 기술 결정 기록

조사 시점은 2026년 11월 16일입니다. 확인하지 못한 항목은 가정이라고 표시했습니다.

## 1. 모듈 구성

- `:core`는 JVM 전용 모듈입니다. 서비스 프로필, 계정과 발신 주소 규칙, 수신 주소 판별, 답장 규칙, MIME 조립과 해석, 폴더 역할 매핑, 발송 상태 기계, 폴더 동기화 알고리즘, HTML 정제, IMAP과 SMTP 게이트웨이가 들어 있습니다. Android 클래스에 의존하지 않아서 JVM 단위 테스트와 통합 테스트로 검증합니다.
- `:app`은 Android 모듈입니다. Room 저장소, 자격 증명 보관, 리포지토리, 동기화와 발송 서비스, 알림, 백그라운드 작업, 화면이 들어 있습니다.
- 서비스 간 차이는 `ProviderProfile` 데이터로만 표현하고 서비스 이름으로 분기하는 코드는 없습니다.

## 2. 메일 라이브러리

| 후보 | 결과 |
| --- | --- |
| `com.sun.mail:android-mail` 1.6.8 (2025-07-23) | 채택. Android 전용 배포판이고, 사용하는 JDK 클래스가 모두 안드로이드 플랫폼에 있습니다. |
| `org.eclipse.angus:angus-mail` 2.0.5 | 제외. 클래스 상수를 검사한 결과 `java.awt.Image`, `java.awt.Toolkit`, `javax.security.sasl.*`를 참조하는데 안드로이드 플랫폼 jar에는 없습니다. 지연 로딩이라 당장 죽지는 않을 수 있지만 검증된 경로가 아닙니다. |
| 직접 구현 | 금지 사항입니다. |

정정: 처음에는 Angus의 `java.awt.datatransfer` 의존이 문제라고 적었으나 `jakarta.activation-api` 2.1.4는 `java/awt` 참조가 0건이었습니다. 실제 사유는 위 표의 `java.awt.Image`, `java.awt.Toolkit`, `javax.security.sasl`입니다.

- 라이선스: 이 jar의 `META-INF/NOTICE.md`는 Eclipse Public License 2.0과 GPL 2.0 클래스패스 예외를 선언합니다. 전문은 `third_party/licenses/`와 앱의 오픈소스 고지 화면에 있습니다.
- IDLE는 `IMAPFolder.idle`, 토큰 인증은 `SMTPTransport$OAuth2Authenticator`와 IMAP XOAUTH2 클래스가 jar에 있습니다. 이번 범위에서 토큰 인증은 동작시키지 않았습니다.
- 알려진 취약점 CVE-2025-7962(SMTP 주입)는 `com.sun.mail:jakarta.mail`이 1.6.8에서 수정된 것으로 공개되어 있습니다. android-mail 1.6.8의 공식 확인 문서는 찾지 못했습니다. 대신 1.6.7과 1.6.8의 클래스 해시를 비교해 `SMTPTransport`를 포함한 변경 클래스 집합이 `jakarta.mail` 1.6.8과 완전히 같음을 확인했습니다(가정: 같은 수정이 들어 있음). 추가 방어로 `mail.mime.allowutf8`를 끄고, 주소와 헤더 값의 줄바꿈과 NUL을 입력 경계에서 거부하며 테스트로 고정했습니다.

## 3. TLS 설정

- 1.6.8의 기본값은 `ssl.checkserveridentity=false`, `starttls.required=false`입니다(바이트코드로 확인). 그래서 모든 프로토콜에 명시적으로 설정합니다. 테스트가 속성 값과 실제 동작(다른 호스트 인증서 거부, STARTTLS 미제공 서버 거부, IP 주소 접속 거부)을 둘 다 확인합니다.
- 인증서 신뢰 우회 설정은 제품 코드에 없습니다. 테스트는 JVM 신뢰 저장소 속성으로, 기기 테스트는 디버그 빌드의 도메인 한정 설정으로 테스트용 인증서만 신뢰합니다.
- 이 라이브러리는 인증서의 DNS 항목만 비교하고 IP 항목은 무시합니다. 실제 메일 서버는 이름으로 접속하므로 문제가 없고, 에뮬레이터 테스트용 인증서는 IP를 이름(CN)에 넣었습니다.
- 개발 중 발견한 결함: 프로토콜 이름이 없는 `URLName("smtp")`로 전송 객체를 만들면 모든 `mail.smtp.*` 설정이 무시되어 암호가 평문으로 나갈 수 있습니다. `SessionConfig.smtpUrl`로 고치고 STARTTLS 테스트(`tlsUsed`)와 단위 테스트로 막았습니다.

## 4. Material 3 Expressive

- 지시문은 Compose Material3 안정판 1.4.0을 전제했습니다. 확인 결과 1.4.0 안정판 jar에는 `ButtonGroup`, `LoadingIndicator`, `ToggleButton`, `SplitButton`, `FloatingToolbar`가 없고 1.5.0 계열에만 있습니다(BOM 2026.09.00은 1.4.0에 매핑).
- 결정: `androidx.compose.material3:material3:1.5.0-rc01`(2026-11-04, 릴리스 후보)을 사용합니다. 나머지 Compose는 BOM 2026.09.00(ui, foundation 1.12.1)입니다. 1.5.0 안정판이 나오면 버전 한 줄만 올리면 됩니다.
- 테마는 `MaterialExpressiveTheme`와 `MotionScheme.expressive()`를 씁니다.
- 화면은 그림자 없이 톤 단계로 묶고, 모양은 둥근 사각형 대신 알약 모양을 씁니다(사용자 결정, 2026-11-16). 설정과 양식 화면의 카드는 예외로 조금 둥근 사각형입니다(29절). 한 줄 높이 부품(버튼, 토글, 칩, 라벨, 한 줄 입력란)은 완전한 알약(`Pill`)이고, 줄과 묶음은 48dp 토큰(`capsuleShape()`)이라 높이 96dp까지는 완전한 알약이 됩니다. 그보다 큰 묶음을 반지름 50%로 만들면 글자가 곡선에 잘리므로 48dp에서 멈춥니다.
- 그림자는 전부 0입니다. 떠 있는 버튼, 툴바, 새로고침 표시는 고도 0으로 두고, 메뉴와 스낵바는 `ui/theme/Surfaces.kt`의 `FlatMenu`, `FlatSnackbarHost`를 씁니다. 겹치는 요소는 톤 차이로 구분합니다(메뉴의 1dp 윤곽선은 36절에서 뺐습니다). 예외로, 메일 화면 툴바가 좁아 동작이 넘칠 때 뜨는 `AppBarRow`의 더 보기 메뉴는 라이브러리 내부라서 기본 그림자가 남습니다.
- 목록과 묶음 화면의 바탕은 `surfaceContainer`, 줄과 묶음은 `surface`입니다. 메일 쓰기, 에이전트 대화처럼 문서 하나인 화면은 `surface`를 유지합니다. 메일 화면은 처음에 문서형이었다가 묶음형으로 바꿨습니다(28절).
- 계정 구분색은 색을 계산하지 않고 동적 색 구성의 역할 쌍 6개(`primaryContainer`, `tertiaryContainer`, `primary`, `tertiary`, `secondaryContainer`, `secondary`와 각각의 on 색)를 순서대로 씁니다. 계정이 7개 이상이면 색이 반복되며 라벨 글자로 구분합니다.
- minSdk가 31이라 동적 색상이 항상 있으므로 고정 대체 색 구성은 두지 않습니다.
- 화면 전환은 `NavHost`에서 `motionScheme`의 느린 spatial과 기본 effects로 지정합니다. 애니메이션 배율이 0이면 전환을 끕니다.
- 메일 화면의 답장, 전체 답장, 전달은 본문 위에 떠 있는 툴바(`HorizontalFloatingToolbar`)에 두고 답장만 아이콘이 붙은 채움 버튼입니다. 폭이 모자라면 `AppBarRow`가 남는 동작을 더 보기 메뉴로 넘깁니다.
- 물결 모양 진행 막대는 쓰지 않습니다. 물결이 계속 움직여서 장식용 무한 애니메이션 금지 규칙에 걸립니다.

## 5. 자격 증명 저장

- `androidx.security:security-crypto`와 `EncryptedSharedPreferences`는 지원 중단되어 쓰지 않습니다.
- 계정마다 Android Keystore의 AES-256-GCM 키를 따로 만들고(StrongBox 우선, 없으면 일반 Keystore), 암호문은 `noBackupFilesDir/credentials/<계정>.bin`에 저장합니다. 추가 인증 데이터(AAD)에 계정 번호를 묶어서 다른 계정의 파일로 바꿔치기해도 풀리지 않습니다. 계정을 지우면 키도 지워집니다.
- 키를 잃었거나 복원으로 키가 없어진 경우 읽기는 조용히 `null`을 돌려주고, 그 계정은 재인증 상태가 되어 알림으로 안내합니다.
- 대안으로 Tink의 AndroidKeysetManager를 검토했으나 추가 의존성이 필요하고 이 용도에는 직접 구현이 40줄 정도라 채택하지 않았습니다.
- 앱은 `allowBackup=false`이고 데이터 추출 규칙과 전체 백업 규칙이 모든 도메인을 클라우드 백업과 기기 간 전송에서 제외합니다.

## 6. 통합 테스트 서버

- GreenMail 2.1.15를 씁니다. GreenMail은 jakarta 이름공간이고 android-mail은 javax 이름공간이라 같은 클래스로더에 두면 `META-INF/javamail.default.providers`가 충돌합니다. 그래서 격리된 클래스로더로 띄웁니다.
- GreenMail에는 STARTTLS가 없습니다(클래스 문자열 검사). iCloud SMTP가 쓰는 587 경로, STARTTLS 구간의 인증서 이름 불일치, 암호화 제거 시도, DATA 전송 중 연결 끊김은 직접 만든 스크립트 소켓 서버(`ScriptedSmtpServer`)로 검증합니다.
- 테스트 서버 검증 결과는 실제 서비스 검증이 아닙니다.

## 7. SDK 버전

- minSdk 31: Material You 동적 색상이 31부터 제공됩니다. 갤럭시 기기의 Android 12 이상을 전제합니다(가정: 대상 기기가 Android 12 이상).
- targetSdk 36: 설치된 에뮬레이터 이미지(Android 36)와 같아서 실제로 실행 검증이 가능합니다.
- compileSdk 37: `androidx.core:core-ktx` 1.19.1이 compileSdk 37을 요구합니다.
- AGP 9.5.1(내장 Kotlin), Kotlin 2.4.21, KSP 2.3.14, Gradle 9.7.0, JDK 21.

## 8. 서체

Pretendard 1.3.9(2023-11-05) 공식 배포본의 `PretendardVariable.ttf`(6.7MB)를 `res/font`에 내장합니다. SIL OFL 1.1이며 라이선스 파일은 `third_party/pretendard/`와 앱 오픈소스 고지에 들어 있습니다. 가변 글꼴 가중치 축은 API 26부터 쓸 수 있고 minSdk가 31이라 별도 대체 구성이 필요 없습니다. 줄 높이는 `LineHeightStyle(Center, Trim.None)`과 `includeFontPadding=false`로 맞춥니다.

## 9. 동기화 방식 비교

| 방식 | 지연 | 비용과 제약 |
| --- | --- | --- |
| 수동 | 새로고침한 때 | 비용 없음 |
| 주기 작업(WorkManager) | 최소 15분, 기기가 더 늦출 수 있음 | 계정이 늘어도 한 번에 묶어 실행. 분 단위 정확도는 약속할 수 없음 |
| 실시간(IMAP IDLE, 사용자가 켜는 포그라운드 서비스) | 거의 즉시 | 계정마다 연결 1개를 항상 유지하고 상시 알림이 보임. 계정이 늘수록 배터리와 서버 연결이 늘어남 |

- 계정별로 방식을 고릅니다. 서버가 IDLE을 광고하지 않으면(네이버는 로그인 전 응답에서 광고하지 않음) 실시간 계정도 5분 간격 확인으로 대신합니다.
- 실시간 서비스는 `specialUse` 유형입니다. 공식 문서상 시간 제한(24시간 중 6시간)은 `dataSync`와 `mediaProcessing`에만 적용되므로 상시 연결에는 `specialUse`를 선언하고 사용 목적 속성을 적었습니다.
- 포그라운드 서비스는 앱이 화면에 있을 때만 시작할 수 있어서, 기기를 다시 켜거나 강제 종료한 뒤에는 앱을 한 번 열어야 다시 시작됩니다.
- 한 연결의 IDLE는 25분마다 NOOP으로 갱신합니다(서버가 30분 무활동 연결을 끊는 경우 대비).
- 배터리 최적화 예외는 설정 화면에서 이유를 설명하고 사용자가 시스템 화면에서 직접 선택하게 합니다.

## 10. 발송

- 발송 대기로 들어가는 시점에 Message-ID를 만들어 저장합니다. 도메인은 보내는 주소의 도메인입니다.
- 상태: 초안, 발송 대기, 전송 중, 서버 수락, 보낸 편지함 저장 완료. 예외 상태: 발송 실패, 결과 불명, 저장 실패.
- SMTP 단계를 추적하는 전송 객체로 DATA 이후의 연결 끊김만 결과 불명으로 분류합니다. 결과 불명은 자동으로 재전송하지 않고 보낸 편지함에서 Message-ID를 조회해 확인한 뒤 사용자가 선택합니다.
- 보낸 편지함에 넣기 전에 같은 Message-ID가 있는지 항상 검색합니다. 서버가 자동 저장한다고 프로필에 적힌 서비스는 직접 저장하지 않고 몇 차례 확인만 하며, 확인되지 않으면 저장 실패로 표시해서 사용자가 직접 저장을 고를 수 있게 합니다.
- 숨은 참조는 서버로 가는 사본에서 빼고 보낸 편지함 사본에만 남깁니다.
- 앱이 전송 중에 종료되면 다음 실행 때 결과 불명으로 복구합니다.

## 11. 폴더 역할

서버가 알려 주는 특수 용도 속성을 우선합니다. 속성이 없으면 알려진 이름(한국어 포함)을 후보로만 제시하고 사용자가 확정해야 지정됩니다. 이름 추측으로 자동 지정하지 않습니다. 매핑은 계정마다 저장합니다.

## 12. 수신 주소 판별

받는 사람과 참조에 그 계정의 발신 주소가 있으면 모두 표시하고, 없으면 서버가 넣는 전달 관련 헤더(`Delivered-To`, `X-Original-To`, 프로필 데이터)를 보며, 둘 다 없으면 미확인입니다. 라벨은 저장하지 않고 표시할 때 계산하므로 나중에 추가한 주소가 과거 메일에도 반영됩니다. 숨은 참조와 메일링 리스트로 온 메일은 판별되지 않을 수 있습니다.

## 13. HTML 메일

jsoup의 허용 목록으로 정제하고(스크립트, 이벤트 속성, 위험한 주소 형식, 폼, 프레임, 스타일 블록 제거, 인라인 스타일은 허용 속성만), 외부 이미지는 기본적으로 막습니다. 표시는 JavaScript를 끈 WebView와 콘텐츠 보안 정책, 모든 하위 요청 차단으로 한 번 더 막습니다. 링크는 실제 주소를 보여 주는 확인 창을 거쳐 외부 브라우저로만 엽니다.

## 14. 사서함 중복

호스트 이름과 로그인 이름(대소문자 무시)이 같으면 같은 사서함으로 보고 거부합니다. Gmail의 점과 `+` 별칭처럼 서비스가 같은 사서함으로 취급하는 변형은 알지 못하므로 막지 못합니다(알려진 제약).

## 15. 본문 읽기

상세 화면의 본문은 IMAP의 지연 읽기(BODYSTRUCTURE를 보고 필요한 부분만 가져옴)로 읽어서 첨부파일 내용을 내려받지 않습니다. 첨부는 이름과 형식과 크기만 목록에 보이고, 누를 때 그 부분만 따로 받습니다(21절). 이 읽기가 실패하면 예외를 삼키지 않고(삼키면 빈 본문이 캐시에 저장됨) 메일 전체를 받아 해석하는 경로로 넘어갑니다. 테스트 서버(GreenMail)의 멀티파트 BODYSTRUCTURE를 라이브러리가 읽지 못해서 실제로 발생한 결함이며 테스트로 고정했습니다.

## 16. 화면 구현 방식

화면은 다섯 곳(계정 추가, 계정 관리, 목록과 발송함, 메일 상세, 작성)을 `docs/ui-brief.md`의 공통 규칙으로 병렬 작업해서 병합했습니다. 병합 뒤 실제 렌더링에서 시스템 액션 바가 Compose 제목을 가리는 문제와 빈 본문 문제를 찾아 고쳤습니다.

## 17. 사전에 제안하지 않고 추가한 의존성과 예외

요청에 없던 추가 항목입니다. 필요하다고 판단해서 먼저 넣었고, 빼려면 아래 사유를 보고 결정하세요.

- jsoup 1.24.1: HTML 메일 정제에 필요합니다(정규식 정제는 안전하지 않아서 직접 만들지 않았습니다).
- `androidx.compose.material:material-icons-core`는 처음에 넣었다가 뺐습니다. 아이콘을 벡터 드로어블로 바꿨기 때문입니다(18절).
- `androidx.compose.material3.adaptive`(adaptive, adaptive-layout, adaptive-navigation 1.3.0): 폴더블 펼친 화면의 목록과 상세 분할에 필요합니다.
- 테스트 전용: GreenMail 2.1.15, `androidx.test:rules`, `androidx.work:work-testing`.
- HTML 본문 보안 정책에 `font-src https://fonts.dustbird.invalid`를 추가했습니다. 내장 서체를 WebView에서 쓰려는 것이며 이 가짜 주소의 요청은 앱이 가로채서 앱 안의 서체 파일로만 응답하고 다른 글꼴 요청은 모두 막습니다. 빼려면 이 항목과 `ResourcePolicy`의 서체 분기를 지우면 되고, 그러면 본문 서체가 기본 산세리프로 바뀝니다.
- 디버그 빌드는 `10.0.2.2` 한 곳에 대해서만 테스트용 인증서(`testfixtures/emulator-server.pem`)를 신뢰합니다. 그 인증서의 개인 키(`testfixtures/*.p12`)가 저장소에 있습니다. 보호할 비밀이 없는 일회용 키이지만, 디버그 APK를 기기에 설치하면 이 신뢰 설정이 함께 들어간다는 점을 알고 쓰세요. 릴리스 빌드에는 이 설정이 없습니다.
- 작업은 `build/mail-client` 브랜치에 있고 `master`에는 병합하지 않았습니다.

## 18. 아이콘과 로고

- 아이콘은 Material Symbols Rounded의 벡터 드로어블(`res/drawable/ic_*.xml`, Apache 2.0)을 씁니다. `google/material-design-icons` 저장소의 Android용 XML을 그대로 받아 `tint` 속성만 뺐습니다. 이에 따라 `androidx.compose.material:material-icons-core` 의존성을 제거했습니다.
- 앱 로고는 사용자가 정한 그림(남색 바탕의 새와 봉투)입니다. 런처 아이콘은 그림을 85%로 줄여 적응형 아이콘 안전 영역에 넣었고, 바탕색은 그림의 가장자리 색 `#2C3554`입니다. 테마 아이콘과 화면 속 작은 표시는 밝기에서 뽑은 단색 그림(`ic_launcher_monochrome`, `ic_bird`)입니다.

## 19. 메일 동작

- 보관, 삭제, 스팸 신고, 폴더 이동은 먼저 목록에서 숨기고(`message.listState = 1`) 나중에 서버에 반영합니다. "실행 취소" 버튼은 약 4초 동안 보이고, 누르면 숨김만 풉니다. 버튼이 사라지거나 다른 메일을 또 옮기면 앞의 것은 바로 서버에 반영합니다. 버튼을 보여 줄 화면이 없을 때(다른 화면으로 넘어간 경우)는 6초 뒤에 반영합니다. 서버 반영이 실패하면 다시 보이게 하고 알립니다. 앱이 그 사이에 종료되면 다음 실행 때 숨김을 모두 풉니다(메일이 사라져 보이는 것보다 되돌아오는 편이 안전).
- 삭제는 휴지통으로 옮기는 것입니다. 이미 휴지통에 있거나 휴지통 폴더가 없는 계정이면 서버에서 바로 지워지므로 확인 창을 먼저 띄웁니다.
- 보관함 폴더가 없으면 전체 메일 폴더(Gmail)를 보관 대상으로 씁니다. 둘 다 없으면 보관하지 않고 알립니다.
- 별표는 서버에 바로 반영하고 실패하면 되돌립니다. 읽음 표시는 기존처럼 다음 동기화 때 반영합니다.
- 답장을 보내면 원본 메일에 답장함 표시를 붙입니다. 원본을 Message-ID로 찾기 때문에 Message-ID가 없는 메일에는 붙지 않습니다.
- 서버가 MOVE를 지원하지 않으면 복사, 삭제 표시, 지우기 순서로 옮깁니다. UIDPLUS가 없으면 폴더 전체 EXPUNGE를 쓰므로 다른 클라이언트가 삭제 표시한 메일도 함께 지워집니다.
- 휴지통과 보관함도 동기화합니다. 그 밖의 폴더는 메뉴에서 열 때 받아옵니다.

## 20. 검색

- 기기에 받아 둔 메일은 보낸 사람, 받는 사람, 제목, 미리보기를 SQL LIKE로 찾습니다.
- "서버에서 더 찾기"는 계정마다 받은편지함, 보관함, 보낸편지함에 IMAP `UID SEARCH TEXT`를 보냅니다(한글이면 `CHARSET UTF-8`). 폴더마다 최신 50통까지 가져옵니다.
- 서버 검색으로 가져온 오래된 메일은 `listState = 2`로 넣어 목록에는 안 보이게 합니다. 이렇게 하지 않으면 "이전 메일 더 보기"가 가장 오래된 번호를 기준으로 삼아서 중간 메일을 건너뜁니다. 나중에 그 구간을 정상적으로 받아오면 일반 메일로 바뀝니다.
- 테스트 서버(GreenMail)는 여러 부분으로 된 메일의 본문 검색을 지원하지 않아서 본문 검색은 머리글 일치로만 테스트했습니다.

## 21. 첨부 파일

- 받은 첨부는 누를 때 서버에서 해당 부분만 받아 캐시 폴더에 두고, `FileProvider`로 다른 앱에 열기 권한만 줍니다. 파일 이름은 경로 문자와 제어 문자를 바꾼 뒤 씁니다.
- 보낼 첨부는 앱 전용 폴더로 복사해 둡니다. `content://` 주소만 받고 합계 15MB까지 허용합니다. 메일 원문을 메모리에서 조립하기 때문에 둔 한도입니다.
- 다른 앱이 공유로 넘긴 주소가 이 앱 자신의 파일 제공자를 가리키면 받지 않습니다. 다른 앱이 이 앱을 시켜서 이미 받아 둔 첨부를 새 메일에 붙이게 만드는 길을 막기 위해서입니다.
- 전달할 때는 원본의 첨부를 받아서 새 초안에 붙입니다.
- 발송 대기 메일의 원문은 데이터베이스가 아니라 앱 전용 폴더의 파일에 둡니다. SQLite 한 행을 읽는 창이 약 2MB라서 첨부가 있으면 읽지 못하기 때문입니다. 숨은 참조를 뺀 원문은 보낼 때 다시 만듭니다.

## 22. 데이터베이스 2판

- 1판에서 2판으로는 Room 자동 마이그레이션을 씁니다(열 추가와 표 추가뿐). 추가된 것: `message.listState`, `outbox.rawPath`, `draft_attachment`, 에이전트용 표 5개.
- 개발 도중의 2판 초기 모양으로는 실제 올리기를 한 번 실행해 봤지만, 최종 2판으로 1판 데이터를 올리는 시험은 따로 하지 않았습니다.

## 23. 다른 앱에서 넘어오는 요청

- `mailto:` 주소, 공유(보내기), 여러 개 공유를 받아 새 메일 쓰기 화면을 엽니다. `mailto:`는 받는 사람, 참조, 숨은 참조, 제목, 본문만 읽고 그 밖의 항목(첨부 지정 등)은 무시합니다. 제목의 줄바꿈은 지웁니다.
- 넘어온 내용은 화면에 채워 보여 줄 뿐 자동으로 보내지 않습니다.

## 24. 에이전트

- 설계와 확인 범위는 [agent.md](agent.md)에 있습니다.
- JSON 처리는 안드로이드 내장 `org.json`, 통신은 `HttpURLConnection`으로 해서 의존성을 늘리지 않았습니다. 그래서 통신 코드는 `app` 모듈에 있고 기기 테스트로 확인합니다.
- 같은 기기 안의 서버에 붙을 수 있도록 `127.0.0.1`과 `localhost`에만 평문 HTTP를 허용했습니다(`res/xml/network_security_config.xml`). 다른 주소는 계속 TLS만 됩니다.

## 25. 알림에서 바로 처리하기

- 새 메일 알림에 읽음, 보관, 삭제 버튼이 있습니다. 읽음은 기기 데이터베이스에만 적고 다음 동기화 때 서버에 반영합니다(기존 읽음 처리와 같은 경로).
- 보관과 삭제는 수신기가 서버에 직접 붙지 않고 WorkManager 작업으로 넘깁니다. 수신기는 약 10초 안에 끝나야 하는데 IMAP 접속 제한 시간이 15초와 30초라서 그 안에 끝난다고 보장할 수 없고, 네트워크가 없을 때 누른 동작이 조용히 사라지면 안 되기 때문입니다. 작업은 네트워크가 연결되면 실행하고 실패하면 30초 간격으로 두 번 더 시도합니다. 세 번 모두 실패하면 메일은 받은편지함에 그대로 남습니다.
- 알림의 삭제는 휴지통으로 옮기는 것만 합니다. 휴지통 폴더가 없거나 보관할 폴더가 없으면 알림을 그대로 두고 앱에서 처리하라는 안내를 띄웁니다. 확인 창을 띄울 수 없는 곳에서 영구 삭제를 하지 않기 위해서입니다.
- 한 계정의 마지막 메일 알림을 지우면 묶음 요약 알림도 함께 지웁니다.

## 26. 받는 사람 추천

- 주소록 권한을 요청하지 않습니다. 기기에 받아 둔 최근 메일 400통의 보낸 사람, 받는 사람, 참조에서 주소를 모아 입력한 글자가 이름이나 주소에 들어 있는 것을 4개까지 보여 줍니다. 내 발신 주소와 이미 넣은 주소는 빼고, 최근 메일의 주소가 앞에 옵니다.

## 27. 목록과 화면 동작에서 고친 것

실제 화면을 돌려 보다가 찾아서 고친 동작입니다. 모두 테스트로 고정했습니다.

- 목록이 맨 위에 있을 때 새 메일이 오면 맨 위에 그대로 보여 줍니다. 전에는 목록이 보던 줄을 기준으로 자리를 지켜서 새 메일이 화면 위쪽에 숨었습니다. 아래로 내려 읽는 중일 때는 자리를 옮기지 않습니다.
- 메뉴(드로어)가 열려 있을 때 시스템 뒤로 가기는 메뉴를 닫습니다. 전에는 앱이 종료됐습니다.
- 외부 이미지 차단 안내를 허용 버튼이 옆에 붙은 캡슐 하나로 줄였습니다. 머리글 영역은 높이가 제한되는데(28절), 전에는 안내가 그 안에 다 들어가지 못해 잘려 보였습니다.
- 보관이나 이동을 서버에 반영하는 도중에 작업이 취소되면 숨겨 둔 줄을 바로 다시 보이게 합니다. 전에는 앱을 다시 켤 때까지 숨은 채로 남을 수 있었습니다.

## 28. 메일 화면 구성

메일 화면이 글자만 나열된 것처럼 보인다는 사용자 의견(2026-11-16)에 따라 문서형에서 묶음형으로 바꿨습니다.

- 바탕은 `surfaceContainer`이고, 보낸 사람과 첨부와 이미지 안내는 각각 `surface` 캡슐, 본문은 `surface` 시트 하나입니다. 머리글과 본문 사이의 구분선은 없앴습니다. 휴대폰에서는 본문 시트가 화면 아래 끝까지 이어지고 위쪽 모서리만 둥급니다. 넓은 화면에서는 목록 화면이 메일 칸을 캡슐로 감싸지 않고, 본문 시트가 네 모서리가 둥근 캡슐이 됩니다.
- 보낸 사람 캡슐은 기본으로 접혀 있고 이름, 주소, 시각, 계정 라벨, 수신 주소 라벨만 보입니다. 누르면 받는 사람, 참조, 날짜, 받은 계정, 수신 주소가 정렬된 표로 펼쳐집니다. 전에는 이 정보가 모두 글자 줄로 나열되어 화면의 절반 가까이를 썼습니다. 접힌 줄의 계정 라벨과 수신 주소 라벨은 목록의 줄과 같은 부품입니다.
- 아바타는 `MaterialShapes.Cookie9Sided` 모양에 보낸 사람 이름의 첫 글자를 넣습니다. 색은 `primaryContainer`로 고정이고 계정 구분색과 관계가 없습니다. 이런 모양은 앱에서 이 한 곳에만 씁니다.
- 첨부는 개수와 파일 이름을 적은 캡슐 한 줄이고, 누르면 목록 시트가 열립니다. "믿을 수 있는 사람이 보낸 파일만 열어 주세요" 문구는 열기 버튼이 있는 시트 안으로 옮겼습니다.
- 별표는 켜면 `tertiaryContainer` 색 면이 생기는 토글 버튼입니다. 상태는 색만이 아니라 채워진 별 아이콘으로도 구분됩니다.
- 답장 툴바가 본문 위에 떠 있으므로 본문 끝이 가려지지 않게 글 본문에는 아래 여백을, HTML 본문에는 같은 크기의 CSS 여백을 둡니다.
- 머리글 영역은 본문에 200dp를 남기는 높이까지 쓰고(높이가 아주 낮은 화면에서는 45%까지), 그보다 길면 그 안에서 스크롤됩니다. 머리글과 본문이 따로 스크롤되는 구조는 그대로입니다. HTML 본문이 자체 스크롤을 가진 WebView라서 하나로 합치지 않았습니다.
- 제목은 낱말 중간에서 줄이 끊기지 않도록 한국어 구 단위 줄바꿈(`LineBreak.Heading`, 글자 언어 `ko`)을 씁니다. Android 13 미만에서는 기본 줄바꿈으로 돌아갑니다.

## 29. 설정과 양식 화면의 카드 모양

에이전트 설정 화면을 본 사용자가 "이런 곳에서는 알약 카드 대신 조금 둥근 사각형 카드를 쓰라"고 정했습니다(2026-11-16). 여러 줄이 들어가는 키 큰 묶음에 48dp 모서리를 쓰면 카드라기보다 부푼 알약처럼 보였습니다.

- 설정, 에이전트 설정, 계정 목록, 계정 상세, 계정 추가 화면의 묶음과 줄은 20dp 토큰(`cardShape()`, `FlatCard`, `cardItemShapes()`)을 씁니다. 한 줄짜리 줄도 알약이 되지 않도록 28dp가 아니라 20dp로 정했습니다.
- 버튼, 토글, 칩, 라벨, 한 줄 입력란은 그대로 알약입니다. 카드 안의 여러 줄 입력란은 카드보다 조금 작은 16dp 토큰입니다.
- 메일 한 통을 나타내는 것(메일 목록과 검색 결과의 줄, 보낼 편지함의 줄, 메일 화면의 보낸 사람 캡슐과 첨부 줄)과 대화 상자, 시트, 스낵바는 48dp 캡슐을 유지합니다. 사용자가 가리킨 곳이 설정 화면이어서 범위를 이렇게 잡았습니다(해석).

## 30. 메일 줄의 표시 줄

목록 줄 아래의 표시 줄은 계정 알약, "첨부" 글자, "받은 주소" 글자가 섞여 있었습니다. 사용자가 셋을 모두 알약으로 넣는 안을 물었고, 논의 끝에 아래로 정했습니다(2026-11-16).

- 계정 라벨만 색을 채운 알약입니다. 받은 주소는 채움 없이 테두리만 있는 알약(`IdentityLabel`)입니다. 셋을 모두 채운 알약으로 하면 목록에서 가장 덜 중요한 줄이 가장 먼저 보이고, 계정 라벨만 색이 있다는 구분 효과가 약해집니다.
- 첨부는 글자 대신 클립 아이콘으로 바꿔 시각 옆, 답장 표시와 별표가 있는 자리로 옮겼습니다. 화면 낭독기에는 "첨부 파일 있음"으로 읽힙니다.
- 같은 줄을 쓰는 검색 결과, 보낼 편지함의 "보내는 주소", 메일 화면의 접힌 머리글에도 같은 부품을 씁니다.

## 31. 실행 취소 반복, 목록 움직임, 주사율

사용자가 보고한 결함과 요청(2026-11-17)에 따른 것입니다.

- 결함: 메일을 밀어서 보관하거나 삭제한 뒤 "실행 취소"를 누르면 메일이 돌아왔다가 곧바로 다시 지워지고, 실행 취소 버튼이 또 떴습니다. 누를 때마다 되풀이됐습니다.
- 원인: 밀기 부품(`SwipeToDismissBox`)의 상태는 줄의 키별로 저장됩니다. 줄이 "밀어서 넘긴 상태"로 목록에서 빠졌다가 실행 취소로 돌아오면 그 상태가 그대로 복원되고, 부품이 복원된 상태를 보고 동작을 다시 실행했습니다.
- 수정: 밀기 상태를 저장하지 않게 했습니다(`remember`로 만든 `SwipeToDismissBoxState`). 돌아온 줄은 항상 제자리 상태로 시작합니다. `MailboxScreenTest`에 밀어서 삭제, 실행 취소, 다시 지워지지 않음을 확인하는 테스트를 넣었고, 고치기 전 코드에서 실패하는 것을 확인했습니다.
- 실행 취소 버튼이 떠 있을 때 다른 메일을 또 옮기면 앞의 버튼을 닫고 새 버튼을 바로 보여 줍니다. 전에는 버튼이 차례를 기다렸는데, 기다리는 사이에 6초가 지나 서버에 반영되어 버튼을 눌러도 되돌릴 수 없는 경우가 있었습니다.
- 메일 목록과 보낼 편지함의 줄은 사라질 때 흐려지면서 아래 줄이 올라오고, 돌아올 때 나타나면서 아래 줄이 내려갑니다(`Modifier.animateItem`, 테마의 `motionScheme`). 애니메이션 배율이 0이면 쓰지 않습니다.
- 주사율: 앱 창이 화면이 지원하는 가장 높은 주사율을 요청합니다(`preferredRefreshRate`). 가변 주사율(ARR) 기기에서는 기본값이 60Hz 안팎이고 위치나 크기가 바뀌는 애니메이션만 자동으로 높아지므로, 화면 전체에 같은 최고 주사율을 요청합니다(`Modifier.preferredFrameRate`). "높음" 범주 대신 숫자를 쓴 이유는 범주가 기기 설정값을 따르기 때문입니다(에뮬레이터에서는 높음이 90Hz였습니다). 앱의 애니메이션은 모두 시간 기준(스프링)이라 프레임 수에 묶인 것이 없습니다.
- 주사율은 요청일 뿐입니다. 사용자가 기기에서 60Hz로 고정했거나 절전 모드이면 시스템이 낮춥니다. 앱이 떠 있는 동안 화면이 높은 주사율을 유지해서 배터리를 더 쓸 수 있습니다. 에뮬레이터 화면은 60Hz뿐이라 120Hz 동작은 확인하지 못했습니다.

## 32. ChatGPT 로그인을 기기 코드 방식으로 변경

- 처음에는 OpenAI의 Sign in with ChatGPT 문서대로 브라우저에서 로그인한 뒤 `127.0.0.1` 주소로 앱에 돌아오는 방식으로 만들었습니다. 사용자가 에뮬레이터에서 실제로 시도했을 때 170초 대기 시간이 지나 실패했습니다(로그인하는 동안 앱을 살려 두는 짧은 서비스의 제한이 약 3분).
- 사용자가 "Codex 웹에서 인증코드를 입력해 인증받는 방식"으로 정했습니다(2026-11-17). Codex CLI의 기기 코드 로그인이며 OpenClaw와 Hermes도 같은 방식을 씁니다.
- 실제 서버 확인(2026-11-17, 로그인 없이): 공식 문서의 등록용 클라이언트로는 기기 코드 요청이 거절됩니다(HTTP 400 `invalid_client`). OpenID 설정 문서에도 기기 인가 주소가 없습니다. Codex 클라이언트로는 코드가 발급됩니다(HTTP 200). 그래서 이 방식은 Codex 클라이언트 등록을 쓰고, 받은 토큰은 Codex 주소(`chatgpt.com/backend-api/codex`)에 씁니다.
- 다른 앱인 것을 숨기지 않습니다. 모든 요청에 `originator: dustbird`와 `User-Agent: Dustbird/<버전>`을 붙입니다(Hermes 소스의 설명: OpenAI는 다른 실행기가 스스로를 밝히도록 요구함).
- 이전 방식의 코드(로컬 콜백 수신, 로그인용 포그라운드 서비스, 등록용 호스트 식별값, 도구를 네임스페이스로 묶는 형식)는 지웠습니다.
- 남은 위험: OpenAI가 다른 앱용으로 문서화한 경로가 아니므로 정책이나 형식이 바뀌면 동작하지 않을 수 있고, 계정에 대한 OpenAI의 판단은 사용자의 몫입니다. 로그인 완료 뒤의 동작은 실제 계정으로 확인하지 못했습니다.

## 33. 메뉴의 계정별 접기

- 계정이 둘 이상일 때 메뉴의 계정 줄을 누르면 그 계정의 폴더 목록이 접히고 다시 누르면 펼쳐집니다. 계정마다 따로 접힙니다(사용자 요청, 2026-11-17).
- 접힌 계정 줄에는 받은편지함의 안 읽은 메일 수를 보여 줍니다. 접어도 새 메일이 있는지 알 수 있게 하기 위해서입니다.
- 접힌 상태는 기기 설정 저장소에 남아 앱을 다시 켜도 유지됩니다.

## 34. 계정 추가: 준비 단계, 아래쪽 버튼, 문장 입력

- 준비 단계는 글만 늘어놓은 화면이었습니다(사용자 지적, 2026-11-17). 주의 문구는 색 있는 카드 하나로, 준비할 내용은 카드 하나로 모았습니다. 순서가 있는 할 일에는 번호를, 알아 둘 내용에는 정보 아이콘을 붙여 구분합니다. 항목 순서는 그대로 둡니다(Gmail은 계정 조건이 먼저 나와야 합니다).
- "준비를 마쳤습니다"는 스위치에서 체크박스로 바꿨습니다(사용자 요청). 스위치는 바로 적용되는 설정에 쓰고, 확인은 체크박스가 맞습니다.
- 계정 추가의 모든 단계에서 버튼을 화면 아래에 고정했습니다(사용자 요청: 엄지로 누르기 편하게). 내용이 길면 내용만 움직이고, 더 내려 볼 내용이 있으면 버튼 위에 가는 선이 보입니다. 창 높이가 480dp보다 낮으면(가로로 눕힌 전화기) 버튼이 입력 칸을 가리지 않도록 이전처럼 내용 끝에 둡니다.
- 계정 정보 단계의 "로그인 확인하기"는 필수 칸(메일 주소, 비밀번호, 계정 이름, 짧은 이름, 로그인 이름, 두 서버의 주소와 포트)에 모두 글자가 있어야 켜집니다(사용자 요청, 2026-11-17). 형식이 맞는지는 이전처럼 버튼을 누른 뒤에 검사해서 칸마다 알려 줍니다. 꺼진 버튼은 이유를 알려 주지 못하므로 형식 오류까지 버튼을 끄는 조건에 넣지는 않았습니다.
- 준비 단계와 문장 입력 창의 긴 글은 낱말 단위로 줄을 바꿉니다(메일 화면의 제목과 같은 방식). 다른 화면의 본문 줄바꿈은 바꾸지 않았습니다.
- 계정 정보 단계에 "문장으로 입력하기"를 넣었습니다(사용자 요청). 에이전트가 글을 읽고 칸을 채우지만 등록은 사용자가 직접 진행합니다. 동작과 제한은 `docs/agent.md` 3절에 있습니다.
  - 비밀번호는 모델을 거치지 않습니다. 에이전트 설정 화면의 "메일 계정의 비밀번호는 전송하지 않습니다"라는 약속을 지키기 위해서입니다. 그래서 문장 한 번으로 등록까지 끝나지는 않고, 비밀번호 입력과 버튼 두 번이 남습니다.
  - 채운 뒤 로그인 확인을 자동으로 시작하지 않습니다. 모델이 틀린 서버를 채웠을 때 비밀번호가 그 서버로 가는 것을 막기 위해서입니다. 같은 이유로 iCloud 메일, Gmail, 네이버 메일에서는 서버 값을 받지 않습니다.
  - 에이전트가 연결되어 있지 않으면 같은 줄이 에이전트 설정으로 안내합니다.

## 35. 선택 모드로 바뀔 때의 움직임

- 메일을 꾹 누르면 위쪽 바, 작성 버튼, 줄의 선택 표시가 한 번에 바뀌어 딱딱하게 보였습니다(사용자 지적, 2026-11-17).
- 위쪽 바: 선택용 바를 평소 바와 같은 종류(같은 높이, 같은 스크롤 상태)로 바꾸고 둘을 서서히 겹쳐 바꿉니다. 높이가 같아서 꾹 누른 줄이 손가락 밑에서 움직이지 않습니다. 평소 바에 둘째 줄(안 읽은 메일 수)이 있을 때는 선택용 바에도 둘째 줄(메일함 이름)을 넣어 높이를 맞춥니다.
- 사라지는 선택용 바는 마지막 선택 상태를 그대로 보여 주면서 흐려집니다. 그러지 않으면 "0개 선택"이 잠깐 보입니다.
- 작성 버튼은 작아지면서 사라지고 커지면서 돌아옵니다.
- 줄: 선택 여부에 따라 서로 다른 목록 부품으로 바꿔 끼우던 것을 하나로 합쳤습니다. 누르는 동안의 물결이 끊기지 않고, 배경색이 서서히 바뀌며, 체크 표시가 커지면서 나타납니다. 선택된 줄에 붙던 라디오 버튼 역할은 없어지고 선택됨 상태만 남습니다(여러 개를 고르는 목록에 라디오 버튼은 맞지 않았습니다).
- 흐려지는 선택용 바의 버튼이 빈 선택으로 눌릴 수 있어서, 빈 목록에 대한 이동, 삭제, 읽음 표시, 별표는 아무 일도 하지 않게 했습니다.
- 시스템에서 애니메이션을 끈 경우에는 모두 즉시 바뀝니다.

## 36. 더 보기 메뉴를 M3 Expressive 메뉴로 변경

- 더 보기 메뉴가 글자만 있는 둥근 상자여서 M3 Expressive처럼 보이지 않았습니다(사용자 지적, 2026-11-17).
- 라이브러리의 새 메뉴 부품(`DropdownMenuPopup`, `DropdownMenuGroup`, 모양을 받는 `DropdownMenuItem`)으로 바꿨습니다. 성격이 다른 동작을 묶음으로 나누고 묶음 사이에 틈을 둡니다. 모든 항목 앞에 아이콘을 붙입니다. 묶음과 항목의 모양, 누를 때의 모양, 열리고 닫히는 움직임은 라이브러리 기본값입니다.
- 그림자는 계속 쓰지 않습니다. 테두리도 뺐습니다. 묶음마다 테두리를 두르면 틈에서 선이 두 겹으로 보여서, 가장 진한 표면 톤(`surfaceContainerHighest`)만으로 구분합니다. 에뮬레이터에서 두 안을 나란히 놓고 골랐습니다.
- 메뉴는 `ui/theme/Surfaces.kt`의 `FlatMenu(groups = …)` 하나로 그립니다. 메일 목록의 두 메뉴(평소, 선택 모드), 메일 화면, 작성 화면이 모두 같은 모양입니다. 메일 화면 툴바가 좁을 때 뜨는 넘침 메뉴는 `AppBarRow`가 직접 그리므로 그대로입니다.
- 아이콘 3개(새로 고침, 사람, 전체 선택)를 Material Symbols Rounded(Apache 2.0)에서 추가했습니다. 원본 SVG의 경로를 그대로 쓰고 세로 위치만 옮겼습니다.

## 37. 임시 저장한 메일을 이어 쓰는 길

- 임시 저장한 메일을 다시 여는 화면이 없었습니다(사용자 지적, 2026-11-17). 기기에 초안은 남아 있었지만 목록으로 보여 주는 곳이 없었고, 서버의 임시보관함에 올라간 사본은 읽기 화면으로만 열렸습니다. 에이전트가 쓴 초안은 대화 안의 버튼으로만 열 수 있었습니다.
- "임시 저장한 메일" 화면을 만들었습니다. 기기에 있는 초안을 모두 보여 주고, 누르면 작성 화면으로 이어집니다. 서랍 메뉴(개수 표시)와 메일 목록의 더 보기 메뉴에서 들어갑니다.
- 서버의 임시보관함 폴더에서 메일을 눌렀을 때, 같은 Message-ID의 초안이 기기에 있으면 작성 화면으로 엽니다. 다른 기기에서 저장한 초안은 기기에 짝이 없어서 이전처럼 읽기 화면으로 열립니다(이어 쓰기는 만들지 않음).
- 확인 중에 본 것: 작성 화면을 닫을 때 자동으로 남는 초안은 서버 임시보관함에 올라가지 않는 경우가 있었습니다(직접 "임시 저장"을 누르면 올라갑니다). 그래서 기기의 목록을 기준으로 삼았습니다. 이 동기화 자체는 이번에 고치지 않았습니다.

## 38. 보내기 취소 시간과 예약 전송

- 사용자 요청(2026-11-17): 보내기를 누른 뒤 몇 초 동안 취소할 수 있게 하고(기본 5초, 설정에서 변경), 보내기 버튼에 예약 전송을 추가.
- 구조: 보낼 편지함 항목에 "이 시각 이후에 보낸다"(`sendAfter`)와 원본 초안(`draftId`)을 추가했습니다(데이터베이스 버전 3, 자동 이전). 기다리는 동안에는 초안을 지우지 않고, 보낼 시각이 되면 그때 초안으로 메일을 만들어 보냅니다. 그래서 취소하면 초안이 그대로 돌아오고, 예약 메일의 날짜 머리글이 예약한 날이 아니라 실제 보낸 시각이 됩니다.
- 취소 시간이 0보다 크면 보내기를 누르는 즉시 작성 화면이 닫히고, 화면 아래에 남은 초와 취소 버튼이 뜹니다. 취소하면 작성 화면이 그 초안으로 다시 열립니다. 이후에는 같은 자리에서 보내는 중, 보냄, 실패를 알려 줍니다. 0이면 이전처럼 작성 화면에 머문 채로 결과를 보여 줍니다.
- 예약 전송은 보내기 버튼 옆 화살표(나눔 버튼)에서 고릅니다. 내일 오전 8시, 내일 오후 1시, 날짜와 시간 고르기. 예약한 메일은 보낼 편지함에 "보내기 예약됨"으로 보이고 "지금 보내기"와 "취소하고 고치기"를 할 수 있습니다.
- 보낼 시각에 깨우는 방법: 60초 이하의 대기는 앱 안의 타이머가 정확히 맞추고, 그와 별개로 지연된 WorkManager 작업을 항상 걸어 둡니다. 앱이 꺼져도 WorkManager가 보냅니다. 정확한 알람 권한은 쓰지 않았으므로 절전 상태에서는 예약 시각보다 몇 분 늦을 수 있고, 그때 인터넷이 없으면 연결된 뒤에 보냅니다.
- 기다리는 초안은 임시 저장 목록에서 숨깁니다. 같은 메일이 두 곳에 보이지 않게 하기 위해서입니다.
- 에이전트의 `send_draft`는 승인 창을 거치므로 취소 시간 없이 바로 보냅니다.
- 만들지 않은 것: 예약한 메일이 백그라운드에서 실패했을 때의 알림(보낼 편지함과 그 배지에는 보입니다), 서버 쪽 예약(메일 서버가 대신 보내 주는 방식).

## 39. 에이전트를 메일 관리자로

- 사용자 요청(2026-11-17): 에이전트는 메일을 찾고, 요약하고, 답장 초안을 쓰고, 정리하는 관리자여야 하고 실제로 그 일을 해야 한다.
- 지시문의 역할을 "메일 관리자"로 바꾸고 네 가지 일의 진행 방식을 적었습니다. 찾기는 검색과 목록 도구로, 요약은 본문을 읽은 뒤에, 답장은 초안을 만들고 알리기, 정리는 먼저 살피고 무엇을 몇 통에 할지 말한 뒤 실행하고 결과를 숫자로 보고. 설명만 하지 말고 도구로 실행하라는 문장을 넣었습니다.
- 시작 화면을 네 가지 일(안 읽은 메일 요약, 답장이 필요한 메일 찾기, 답장 초안 쓰기, 받은편지함 정리)로 바꿨습니다. 줄마다 실제로 보낼 요청 문장이 보이고, 누르면 그 일을 시작합니다.
- `list_accounts`가 계정별 안 읽은 메일 수를 함께 돌려줍니다. 관리자가 전체 상황부터 볼 수 있게 하기 위해서입니다.
- 도구와 승인 규칙은 그대로입니다. 읽음 표시와 이동은 기본으로 묻고, 보내기와 기억 저장은 항상 묻습니다. 에이전트가 쓴 답장 초안은 37절의 "임시 저장한 메일"에 나오므로 사용자가 고쳐서 보낼 수 있습니다.
- 확인 범위: 가짜 모델로 찾기, 읽기, 답장 초안, 읽음 표시가 실제 데이터에 반영되는 것을 기기 테스트로 확인했습니다. 실제 모델이 이 지시문을 얼마나 잘 따르는지는 확인하지 못했습니다.

## 40. 기능 점검에서 찾아 고친 것

사용자 요청(2026-11-17)에 따라 메일 앱에 필요한 기능이 제대로 들어 있는지 점검했습니다. 코드를 네 영역(받기, 읽기, 쓰기와 보내기, 계정과 목록)으로 나눠 따로 읽고, 에뮬레이터에서 시험 메일을 넣고 눌러 보며 확인했습니다. 아래는 그 결과로 고친 것입니다. 앞 절의 내용과 다른 곳은 이 절이 우선합니다.

보내기와 초안

- 붙인 첨부가 사라지고 첨부 없이 발송되던 결함: 초안을 다시 저장할 때 행을 지웠다가 다시 넣는 방식(`INSERT OR REPLACE`)이라 첨부 행이 연쇄 삭제됐습니다. 글자를 치면 1.5초 뒤 첨부가 사라졌고, 보내기 직전에도 저장하므로 메일이 첨부 없이 나갔습니다. 초안은 새로 넣기와 고치기로 나누고, 서버 사본 표시는 그 칸만 고칩니다. 기존 테스트는 첨부한 뒤 다시 저장하지 않아서 놓쳤습니다.
- 메일을 만들다 실패하면 보낼 편지함 항목이 풀리지 않아 그 계정의 발송과 주기 동기화가 멈추던 문제: 실패로 표시하고 "취소하고 고치기"를 보여 줍니다. 한 계정의 문제가 다른 계정을 막지 않습니다. 답장 대상의 Message-ID에 `@`가 없어도 받아들이고, 긴 References는 접어서 씁니다.
- 보내지 못한 메일은 알림으로 알립니다(38절의 "만들지 않은 것"에서 바뀜). 화면에 전송 상태가 떠 있는 동안에는 알림을 띄우지 않습니다.
- 예약한 메일을 깨우는 작업은 앱을 켤 때와 발송 작업이 끝날 때 다시 걸어 둡니다. 예약되어 기다리는 초안은 임시보관함 폴더에서 눌러도 작성 화면으로 열리지 않습니다. 첨부를 붙이는 중에는 보내기를 받지 않습니다.
- 보낸 뒤 30일이 지난 보낼 편지함 기록과 보낸 메일의 원문 파일은 앱을 켤 때 정리합니다. 계정을 지우면 그 계정의 발송 원문, 초안 첨부, 받은 첨부 파일도 지웁니다.

받기와 알림

- 보낸 사람 주소가 다른 주소로 보일 수 있던 결함: 주소 머리글을 먼저 디코딩한 뒤 해석해서, 인코딩된 표시 이름 안의 주소가 실제 주소 자리를 차지했습니다. 원문을 먼저 해석한 뒤 이름만 디코딩합니다. 이름에 다른 메일 주소가 들어 있으면 이름을 버리고 실제 주소를 보여 줍니다. 이름의 쉼표와 콜론도 그대로 보입니다.
- 알림 권한은 받은편지함이 처음 보일 때 한 번 묻습니다. 전에는 설정 화면의 버튼으로만 물어서 새로 설치하면 알림이 오지 않았습니다. (54절에서 팝업으로 바꿈)
- 새 메일 알림은 받은편지함을 받은 직후에 올립니다. 전에는 뒤 폴더에서 오류가 나면 그 알림이 영영 빠졌습니다. 다른 기기에서 이미 읽은 메일은 알리지 않고, 앱에서 읽거나 옮긴 메일의 알림은 지웁니다. 다시 로그인하라는 알림은 처음 실패했을 때 한 번만 올리고 성공하면 지웁니다. 백그라운드 주기 작업은 암호가 틀린 계정에 다시 로그인하지 않습니다.
- 실시간 수신은 앱이 화면에 올 때마다 다시 확인해서 켭니다. 전에는 백그라운드 작업이 먼저 프로세스를 띄운 경우와 암호를 고친 뒤에 다시 시작되지 않았습니다. 방식을 바꾸거나 계정을 지우면 열려 있던 연결을 바로 닫습니다. 연결을 다시 맺는 사이에 온 메일은 폴더의 다음 번호를 비교해 받아옵니다.
- 읽은 메일을 곧바로 옮기면 서버에 안 읽은 상태로 옮겨지던 문제: 옮기기 전에 읽음 표시를 먼저 올립니다(19절의 "다음 동기화 때 반영"에 더해짐).

읽기

- 일반 글 본문의 웹 주소와 메일 주소를 누를 수 있습니다. 웹 주소는 HTML 메일과 같은 확인 창을 거칩니다.
- 메일 속 메일 주소 링크는 이 앱의 작성 화면으로 엽니다. 전에는 다른 앱을 고르는 창이 떴습니다.
- 이름이 없는 그림, 일정 초대(`text/calendar`), 첨부된 메일은 버려지거나 이름 없이 보였는데, 첨부 목록에 `image.png`, `invite.ics`, `message.eml` 같은 이름으로 보여 줍니다. 열 때는 파일 이름의 확장자로 형식을 정하고, 긴 한글 이름은 바이트 길이에 맞춰 줄입니다. 크기는 인코딩 전 크기에 가깝게 보여 줍니다.
- HTML 정제: `background` 축약형, `display`, `border-radius`를 허용했습니다. 배경색이 지워져 흰 바탕에 흰 글자가 되던 버튼이 보이고, 숨겨 둔 미리보기 문구는 숨겨집니다. 본문 전체가 `form` 안에 든 메일은 입력 칸만 지우고 내용은 남깁니다.
- "외부 이미지 차단" 안내는 허용하면 볼 수 있는 이미지만 셉니다. 본문 속 이미지(cid)처럼 허용해도 볼 수 없는 것은 따로 셉니다.
- 문자셋: windows-1252나 iso-8859-1로 온 영문의 굽은 따옴표가 한글로 깨지던 문제를 고쳤습니다. 한글로 잘못 표시된 경우는 한글 비율이 높을 때만 한글로 읽습니다. 낱말에 붙어 있는 인코딩 제목(`Re:=?UTF-8?…`)도 풉니다. 잘못된 base64와 틀린 전송 인코딩 이름은 오류 대신 읽을 수 있는 만큼 보여 줍니다.
- HTML만 있는 메일에 답장할 때 인용문의 문단이 한 줄로 붙던 문제를 고쳤습니다.
- 본문이 아주 큰 메일(약 60만 자 이상)은 기기에 저장하지 않고 열 때마다 받아옵니다. 한 행이 2MB를 넘으면 다시 읽을 때 앱이 종료될 수 있어서입니다(직접 재현하지는 못했습니다).

목록과 검색

- 검색 결과를 열었다 돌아오면 검색어와 결과가 사라지던 문제를 고쳤고, 한 글자로도 찾습니다.
- "서버에서 더 찾기"가 찾은 메일은 제목이나 미리보기에 낱말이 없어도 결과에 보여 줍니다. 전에는 기기 검색을 다시 돌려서 본문에만 있는 낱말은 나오지 않았습니다. 에이전트의 검색 도구도 같이 고쳤습니다.
- "다른 폴더"의 폴더는 열 때 받아옵니다(19절의 설명대로 동작하게 함). 하위 폴더는 전체 경로로 보여 줍니다. Gmail의 전체 메일 폴더를 메뉴에 넣어 보관한 메일을 볼 수 있게 했고, 보관함이 없는 계정의 서버 검색은 그 폴더에서 찾습니다.
- 받아 둔 메일을 모두 옮겨 목록이 비어도 "이전 메일 더 보기"로 더 오래된 메일을 불러올 수 있습니다.
- 메일 화면에서 삭제, 보관, 이동을 하면 목록으로 돌아왔을 때 "실행 취소"가 보입니다. 옮길 폴더가 없으면 그 자리에서 알려 줍니다.
- 알림으로 연 뒤 화면을 돌리면 같은 메일이 다시 열리던 문제, 계정 없이 시작한 뒤에는 알림과 공유가 화면을 열지 못하던 문제를 고쳤습니다. `mailto:` 주소와 함께 넘어온 제목과 본문도 받습니다.
- 계정의 알림 스위치는 누르는 즉시 적용됩니다.

고치지 않고 남긴 것

- 본문 속 이미지를 본문에 그리기, 첨부된 메일을 앱 안에서 보기, 일정 초대에 답하기, 대화로 묶어 보기, 폴더 만들기와 이름 바꾸기와 지우기, 휴지통 비우기, 휴지통과 보관함 역할을 직접 고르는 화면, 실패한 메일을 고쳐 다시 보내기, 원문과 머리글 보기, 이전과 다음 메일로 넘기기, 첨부 공유, 본문 미리 받기, 서식 있는 글 쓰기, 테마와 밀기 동작 설정은 만들지 않았습니다. 새 기능이라 사용자 결정이 필요합니다.
- 서버에서 지워지거나 읽힌 메일을 기기에 반영하는 범위는 폴더마다 최신 500통입니다. 실시간 수신의 재접속 타이머는 기기가 깊이 잠들면 늦어질 수 있습니다. 인코딩 없이 EUC-KR 바이트로 온 제목과 보낸 사람 이름은 깨져 보입니다(본문은 정상).

## 41. Outlook 메일과 Microsoft 로그인

- 사용자 요청(2026-11-18): Outlook 메일도 추가할 수 있게.
- Outlook 개인 계정은 비밀번호와 앱 비밀번호로 IMAP과 SMTP에 로그인할 수 없고 OAuth 2.0만 됩니다(Microsoft 지원 글, 2024년 9월 16일부터). 그래서 다른 서비스처럼 서버 값만 넣어서는 연결되지 않고 토큰 인증을 만들었습니다.
- 로그인은 기기 코드 방식입니다. 앱이 보여 주는 코드를 Microsoft 로그인 페이지에 입력합니다. 에이전트의 ChatGPT 로그인과 같은 모양이고, 브라우저에서 앱으로 돌아오는 주소를 등록할 필요가 없습니다.
- 애플리케이션 ID 칸에는 Thunderbird 메일 앱의 공개 ID(`9e5f94bc-e8a4-4e73-b8be-63364c29d753`)가 기본으로 들어 있습니다. 처음에는 직접 등록한 ID만 받게 만들었는데, 등록 절차를 들은 사용자가 Thunderbird ID를 기본값으로 넣기로 정했습니다(2026-11-18). 실제 서버에 로그인 없이 요청해 이 ID로 기기 코드가 발급되는 것을 확인했습니다. 로그인 화면에는 Thunderbird로 표시되고, Microsoft나 Mozilla가 이 사용을 막으면 연결되지 않습니다. 직접 등록한 ID로 바꿔 넣을 수 있고, 로그인에 쓴 ID는 기기 설정에 남습니다.
- 저장: 접근 토큰과 갱신 토큰을 계정 암호 자리에 암호화해 둡니다(`TokenCredentialStore`). 만료 2분 전부터 갱신하고, 갱신이 거절되면 암호가 없는 것으로 처리해서 기존의 "다시 로그인 필요" 흐름으로 갑니다. 계정 상세의 다시 로그인은 Outlook 계정이면 비밀번호 칸 대신 Microsoft 로그인을 보여 줍니다.
- 연결: 토큰은 표시가 붙은 비밀 값으로 전달되고, IMAP과 SMTP 설정이 그 표시를 보고 XOAUTH2를 고릅니다. 호출하는 쪽 코드는 바뀌지 않습니다.
- 데이터베이스는 바뀌지 않았습니다(`authMethod` 열은 처음부터 있었습니다).
- 확인 범위: 저장과 갱신 규칙은 단위 테스트로, 코드 발급과 승인 대기와 토큰 교환과 갱신은 기기 안의 가짜 서버로 확인했습니다. 실제 Microsoft 서버로는 가짜 ID를 보내 주소와 오류 형식만 봤습니다. 실제 Outlook 계정의 로그인, 수신, 발송은 확인하지 못했습니다. 개인 계정에서 SMTP 토큰이 거부된다는 보고가 있어, 처음 연결할 때 SMTP 점검 결과를 꼭 봐야 합니다.
- 만들지 않은 것: Gmail의 토큰 인증, 회사 계정용 서버 자동 선택, 이 앱 이름으로 등록한 애플리케이션 ID.

## 42. 검색 필터, 받은편지함 요약, 에이전트와 쓰기, 보낼 편지함 카드

사용자 요청(2026-11-18)에 따른 것입니다.

검색

- 검색어 아래에 필터 칩 줄을 넣었습니다. 기간(오늘, 최근 7일, 최근 30일, 올해, 날짜와 시간 고르기), 폴더(받은편지함, 보낸편지함, 보관함, 스팸, 휴지통), 계정(둘 이상일 때), 찾을 곳(모든 항목, 보낸 사람, 받는 사람, 제목), 안 읽음, 별표, 첨부입니다. 하나라도 고르면 "필터 지우기"가 나옵니다.
- 검색어 없이 필터만 골라도 찾습니다. 결과 위에 개수를 보여 줍니다.
- 날짜와 시간 고르기는 아래에서 올라오는 창에서 시작과 끝의 날짜와 시각을 따로 고릅니다. 끝 시각은 그 분까지 포함합니다.
- 필터는 기기 데이터베이스에서 한 번에 거릅니다. "서버에서 더 찾기"는 이전처럼 검색어로만 서버에 묻고, 가져온 메일에도 같은 필터를 적용합니다.
- 받는 사람 검색에 참조도 포함합니다.
- 메뉴(`FlatMenu`)가 글자로 된 항목과 고른 항목의 체크 표시를 받을 수 있게 했습니다.

받은편지함 요약

- 에이전트가 연결되어 있고 전송에 동의한 상태이면, 최근 30일 안에 받은편지함에 들어온 메일을 한 줄로 요약해 메일 목록의 미리보기 자리에 보여 줍니다. 요약 앞에는 작은 새 아이콘을 붙여 원문 미리보기와 구분하고, 화면 낭독기는 "에이전트 요약"이라고 읽습니다. 검색 결과에도 같은 요약이 보입니다.
- 요약은 새 메일이 왔을 때, 새로 고칠 때, 에이전트를 연결했을 때 만듭니다. 한 번에 5통씩 묶어 모델에 보내고, 한 번 실행에 20통까지만 만듭니다. 본문이 기기에 없으면 서버에서 받아 오며(그 뒤로는 오프라인에서도 읽힘), 인용문은 빼고 3000자까지만 보냅니다.
- 모델이 돌려준 요약은 80자로 자르고, 보낸 묶음에 없는 메일 번호는 버립니다. 메일 본문 속 지시문은 따르지 않도록 지시하고, 본문에 든 태그 모양 글자는 바꿔서 보냅니다. 막아 둔 계정의 메일은 보내지 않습니다.
- 모델이 요약을 빠뜨린 메일은 빈 요약으로 기록해 원래 미리보기를 보여 주고, 같은 메일을 계속 다시 보내지 않습니다.
- 에이전트 설정의 "받은편지함에 요약 보여 주기"로 끌 수 있습니다(기본 켜짐). 끄거나 연결을 끊으면 요약을 숨기고 더 보내지 않습니다.
- 요약은 새 표 `message_digest`에 둡니다(데이터베이스 4판, 자동 이전). 메일이 지워지면 함께 지워집니다.

에이전트와 쓰기

- 작성 화면의 본문 위에 "에이전트와 쓰기" 버튼을 넣었습니다. 창에서 원하는 내용을 적거나, 쓴 글이 있으면 다듬기, 짧게, 더 정중하게, 맞춤법 고치기를, 답장이면 답장 초안을 고릅니다.
- 초안은 창 안에 먼저 보여 주고, "본문에 넣기"를 눌러야 들어갑니다. 넣을 때 사용자가 쓴 부분만 바꾸고 인용한 원문과 서명은 그대로 둡니다. 제목은 비어 있을 때만 채웁니다. 보내기는 사용자가 직접 누릅니다.
- 모델에는 요청, 쓰고 있는 글, 받는 사람 이름, 인용한 원문을 보냅니다. 서명은 보내지 않습니다. 원문 속 지시문은 따르지 않도록 지시하고, 모르는 내용은 대괄호로 비워 두게 했습니다.
- 에이전트가 연결되어 있지 않으면 창이 에이전트 설정으로 안내하고, 보내는 계정이 막아 둔 계정이면 쓰지 않습니다.

보낼 편지함

- 보낼 편지함의 항목을 설정 화면과 같은 20dp 카드로 바꿨습니다(29절에서 메일 한 통을 나타내는 것은 48dp 캡슐로 두었던 것을 사용자 지적에 따라 바꿈). 메일 목록과 검색 결과의 줄은 그대로 캡슐입니다.

확인 범위: 필터 검색, 요약 저장과 표시와 차단 계정 제외, 에이전트와 쓰기의 넣기 규칙은 기기 테스트로, 화면은 에뮬레이터와 가짜 모델 서버로 확인했습니다. 실제 모델이 요약과 초안을 얼마나 잘 쓰는지는 확인하지 못했습니다.

## 43. ChatGPT 모델 목록 동기화, Codex 버전, Java4Shell 점검

사용자 요청(2026-11-18)에 따른 것입니다.

모델 목록

- ChatGPT 로그인 방식에서는 모델 이름을 직접 적지 않고 목록에서 고릅니다. 목록은 Codex가 쓰는 `GET https://chatgpt.com/backend-api/codex/models?client_version=<Codex 버전>`에서 받아 옵니다. 로그인 직후와 에이전트 설정 화면을 열 때마다 새로 받고, 창의 "다시 받기"로도 받습니다.
- Codex와 같은 규칙으로 `visibility`가 `list`인 모델만 `priority` 오름차순으로 보여 줍니다. 모델 아이디는 영문, 숫자, 점, 밑줄, 콜론, 하이픈 100자 이내만 받고, 이름은 60자, 설명은 200자로 자릅니다. 응답은 4MB까지만 읽습니다.
- 받은 목록은 설정 저장소에 두어 다음에 열 때 바로 보이고, 받아 오지 못하면 마지막 목록을 보여 줍니다. 로그아웃하면 지웁니다.
- 맨 위의 "자동"은 모델을 저장하지 않고 목록 맨 앞의 기본 모델을 씁니다. 목록이 아직 없으면 이전처럼 `DEFAULT_MODEL`을 씁니다. 고른 모델이 새 목록에서 빠지면 "지금 목록에 없는 모델"로 표시합니다.
- API 키와 내 서버 방식도 연결을 저장하면 그 서버의 `GET {서버 주소}/models`(OpenAI 호환 형식, 같은 키로 요청)에서 목록을 받아 고릅니다. 주소나 키를 새로 저장하면 목록을 지우고 다시 받습니다. 서버가 Codex 형식(`models`)으로 답하면 위와 같은 규칙을 씁니다.
- 공식 OpenAI 주소일 때는 대화에 쓰는 글 모델만 남깁니다(이름이 gpt-, chatgpt-, codex-, o1, o3, o4로 시작하고 embedding, tts, transcribe, audio, realtime, image, search, moderation, whisper, dall-e, instruct, diarize가 들어가지 않는 것). 만든 날짜가 새로운 순서로 보여 줍니다. 다른 서버는 받은 목록을 그대로 보여 줍니다.
- API 키 방식의 "자동"은 이전 기본값 `DEFAULT_MODEL`(gpt-6.1-sol), 내 서버는 `GATEWAY_MODEL`(openclaw)을 그대로 씁니다. 사용량만큼 요금이 나오는 방식이라 가장 새 모델로 저절로 바뀌지 않게 했습니다.
- 목록은 연결 방식마다 따로 저장합니다(`agent_models_chatgpt`, `agent_models_api_key`, `agent_models_gateway`). 모델 값은 방식끼리 같이 쓰므로, 연결 방식이 바뀌면 고른 모델을 "자동"으로 되돌려 다른 서버에 없는 모델이 넘어가지 않게 했습니다.

Codex 버전

- 모델 목록은 서버가 `client_version`보다 높은 버전을 요구하는 모델을 빼고 돌려주므로, 목록을 받을 때마다 GitHub의 openai/codex 최신 정식 릴리스(`releases/latest`, 미리 보기 제외)에서 버전을 읽어 씁니다. `rust-v` 뒤의 숫자 세 마디 형식만 받습니다.
- 읽지 못하면 마지막으로 읽은 버전을, 그것도 없으면 내장 값(`FALLBACK_VERSION`, 0.170.0)을 씁니다. GitHub 요청에는 앱 이름 외에 사용자 정보를 보내지 않습니다.

Java4Shell(CVE-2026-114938)

- HotSpot의 AVX-512 VBMI Base64 디코딩 내장 함수의 힙 넘침이며 x86-64 CPU에서만 해당합니다. 앱은 안드로이드 ART에서 돌아 해당하지 않고, 이 개발 기기는 Apple M1 Pro(arm64)라 빌드와 테스트 JVM도 해당하지 않습니다.
- 다른 x86-64 기기에서 고쳐지지 않은 JDK로 돌릴 때를 위해, 프로젝트가 직접 띄우는 JVM(core 테스트, 테스트 메일 서버 `runTestServer`)에 권고된 완화 옵션 `-XX:-UseBASE64Intrinsics`를 넣었습니다. 테스트 메일 서버는 네트워크로 받은 Base64(AUTH)를 디코딩하므로 가장 노출된 곳입니다.
- Gradle 데몬에는 넣지 않았습니다(외부 입력을 디코딩하지 않음).

확인 범위: 목록 파싱, 공식 OpenAI 목록 거르기, 최신 버전 읽기, 인증 실패, 로그인 직후 동기화, 자동 모델, 방식이 바뀔 때 모델 되돌리기는 기기 테스트로, 고르기 창은 가짜 서버를 둔 화면 테스트와 에뮬레이터 화면으로 확인했습니다. 실제 ChatGPT 계정, 실제 OpenAI API 키, OpenClaw와 Hermes 서버로 목록을 받는 것은 확인하지 못했습니다.

## 44. iCloud 내 도메인 주소와 비밀번호 칸 접근성 노출

사용자 지적(2026-11-18)에 따른 것입니다.

iCloud 내 도메인 주소

- iCloud에 연결한 내 도메인 주소(예: 이름@내도메인)로 계정을 추가하면 로그인 이름이 그 주소로 채워져 로그인이 거부되었습니다. Apple 안내는 다른 메일 앱의 로그인 이름으로 iCloud 메일 주소를 쓰라고 하고, 내 도메인 주소는 그 계정에 붙은 별칭입니다.
- 주소의 도메인이 icloud.com, me.com, mac.com이 아니면 로그인 이름을 비워 두고, 주소 아래에 기본 iCloud 메일 주소를 넣으라는 안내를 보여 주며, 고급 설정을 펼칩니다. 로그인 이름을 넣기 전까지 로그인 확인 버튼은 꺼져 있습니다.
- 이 앱은 받기와 보내기에 같은 로그인 이름을 쓰므로, iCloud 로그인 실패 안내에서 "@ 앞부분만 입력" 권고를 빼고 기본 iCloud 메일 주소 전체를 넣으라고 바꿨습니다(보내는 서버는 전체 주소를 요구).
- 같은 iCloud 계정을 이미 추가했다면 내 도메인 주소는 새 계정이 아니라 그 계정의 보내는 주소로 추가합니다(같은 서버와 로그인 이름은 중복 계정으로 막힘).

비밀번호 칸 접근성 노출

- Compose `SecureTextField`는 화면에는 점으로 가리지만 접근성 정보의 `EditableText`와 `InputText`에 원래 글자를 그대로 실었습니다. 노드에 비밀번호 표시는 있었지만, 접근성 서비스 앱은 누구나 실제 값을 읽을 수 있었습니다(실제 기기 화면 덤프로 확인).
- 가려 둔 동안에는 두 속성을 같은 길이의 점으로 바꾸는 `hiddenSecret`을 계정 추가, 재인증, 에이전트 키와 접속 토큰 칸에 붙였습니다. "보기"를 눌러 화면에 보일 때만 원래 글자를 내보냅니다. 자동 채우기(`FillableData`)는 그대로 두어 비밀번호 관리자는 계속 쓸 수 있습니다.

확인 범위: 로그인 이름 규칙은 core 테스트로, 안내와 고급 설정 펼침과 접근성 가림은 화면 테스트와 에뮬레이터 화면 덤프로 확인했습니다. 실제 iCloud 서버에서 내 도메인 주소와 기본 주소로 로그인이 갈리는 것은 직접 확인하지 못했습니다.

## 45. ChatGPT 응답을 읽지 못하던 문제와 오류 내용 표시

사용자 지적(2026-11-18)에 따른 것입니다.

- 실제 기기에서 ChatGPT 로그인으로 처음 요청을 보내자 "에이전트 서버에서 문제가 생겼습니다"가 떴습니다. ChatGPT 백엔드는 SSE 스트림으로 답하면서 Content-Type 머리글을 보내지 않았고(`null`), 앱은 `text/event-stream`이 아니면 JSON 한 덩어리로 읽어 파싱에 실패했습니다.
- 이제 머리글 대신 응답 내용으로 판단합니다. 첫 글자(공백 제외)가 `{`이면 JSON, 아니면 SSE로 읽습니다.
- 응답을 읽지 못하면 오류에 Content-Type, 이벤트 이름, 읽지 못한 내용 앞 60자를 붙입니다.
- 문장으로 입력하기와 에이전트와 쓰기 창은 실패 문구 아래에 "서버가 알려 준 내용"을 보여 줍니다. 서버 응답이 아닌 예외도 종류를 함께 보여 줍니다. 에이전트 요청이 실패하면 기기 로그(태그 `Dustbird`)에 출처, 종류, 내용을 한 줄 남깁니다. 비밀번호와 메일 본문은 남기지 않습니다.

확인 범위: 실제 기기에서 ChatGPT 로그인으로 문장으로 입력하기가 칸을 채우는 것까지 확인했습니다(개인정보 없는 시험 문장). 에이전트 대화, 받은편지함 요약, 에이전트와 쓰기, 모델 목록 동기화는 실제 계정으로 아직 확인하지 않았습니다.

## 47. 받은 주소 미확인 줄이기

사용자 지적(2026-11-19)에 따른 것입니다.

실제 기기(iCloud 계정 1개, 보내는 주소는 내 도메인 주소 1개)에서 152통 중 91통이 "받은 주소: 미확인"이었습니다. 46통은 보낸편지함의 보낸 메일이었고, 받은 메일 45통은 같은 메일함의 다른 주소(기본 iCloud 주소 7, 이메일 가리기 주소 10, 같은 내 도메인의 다른 주소 28)로 온 것이었습니다. iCloud는 `Delivered-To`와 `X-Original-To`를 넣지 않아 머리글로도 알 수 없었습니다.

- 보낸편지함과 임시보관함의 메일에는 받은 주소를 보이지 않습니다(`RecipientMatch.NotReceived`).
- 보내는 주소와 맞지 않으면 그 계정의 내 주소인지 봅니다(`RecipientMatch.OwnAddress`). 맞으면 "받은 주소" 알약에 실제로 받은 주소를 그대로 보여 줍니다.
  - 모든 서비스: 로그인 이름이 메일 주소이면 그 주소.
  - iCloud만: 보내는 주소에 쓰인 내 도메인과 같은 도메인의 주소(내 도메인의 모든 주소 받기 대응), icloud.com, me.com, mac.com, privaterelay.appleid.com 주소(이메일 가리기, Apple로 로그인 중계).
  - 회사 도메인처럼 다른 사람도 같은 도메인을 쓰는 경우를 잘못 내 주소로 보지 않도록, 도메인 규칙은 iCloud에만 둡니다.
- 위에 해당하지 않으면(숨은 참조, 메일링 리스트, 앱이 모르는 다른 내 도메인) 이전처럼 미확인입니다. 그 도메인의 주소를 보내는 주소로 하나 추가하면 같은 도메인 메일이 모두 내 주소로 보입니다.
- 답장할 때 보내는 주소를 고르는 규칙은 바꾸지 않았습니다(보내는 주소와 맞을 때만 그 주소, 아니면 기본 주소).

같은 규칙을 기기 데이터 사본에 적용하면 받은 메일의 미확인은 45통에서 2통(앱이 모르는 다른 도메인)으로 줄고, 보낸 메일 50통에는 표시가 없습니다.

## 48. 이메일 가리기 주소로 답장

사용자 요청(2026-11-19)에 따른 것입니다.

- iCloud 계정에서 받은 메일이 로그인 주소가 아닌 icloud.com, me.com, mac.com 주소(이메일 가리기 주소)로 왔으면, 답장을 시작할 때 그 주소를 계정의 보내는 주소로 추가하고 답장의 보내는 주소로 고릅니다. 작성 화면의 답장과 에이전트가 쓰는 답장 초안에 적용합니다. 메일 보기 화면이 답장 받는 사람을 미리 계산할 때는 추가하지 않습니다.

- 보내는 주소가 된 뒤로는 그 주소로 온 메일에 라벨이 보이고, 전체 답장 받는 사람에서도 빠집니다. Apple로 로그인 중계 주소(privaterelay.appleid.com)는 그 주소로 보낼 수 없어 제외합니다.
- Apple 안내에 따르면 이메일 가리기 주소로 답장할 수 있지만 받는 사람은 한 명만 됩니다. 다른 메일 앱에서 iCloud SMTP가 이 주소를 거부했다는 사용자 글도 있어, 실제 발송은 확인이 필요합니다. 거부되면 기존 발송 실패 알림으로 알려 줍니다.
- 작성 화면은 답장 준비 뒤 보내는 주소 목록을 다시 읽습니다(새로 추가된 주소를 찾기 위해). 에이전트의 초안 도구도 같습니다.

테스트 정리: `ComposeViewModelTest.autosaveStoresTheDraftAfterTypingStops`는 화면 없이 뷰모델만 쓰는데, 같은 프로세스에서 화면 테스트가 먼저 돌지 않으면 스냅샷 변경 알림이 오지 않아 자동 저장이 깨어나지 않았습니다(실제 앱과 무관). 테스트에서 `Snapshot.sendApplyNotifications()`를 직접 부르게 했습니다.

## 50. 메일 본문 카드가 스크롤하면 화면을 채움

사용자 요청(2026-11-19)에 따른 것입니다.

- 이전에는 제목과 보낸 사람 칸이 위에 고정되고, 본문 카드는 그 아래 남은 자리에서 따로 스크롤했습니다. 제목이 길거나 첨부와 이미지 안내가 있으면 본문 카드가 화면의 절반도 되지 않았습니다.
- 이제 메일 화면 전체가 한 번에 스크롤합니다. 위로 밀면 제목과 보낸 사람 칸이 올라가고 본문 카드가 위쪽 막대 아래부터 화면을 채웁니다. 본문이 짧으면 카드가 남은 자리를 채우고 스크롤하지 않습니다.
- 본문 WebView는 내용 높이만큼 커지고 자기 세로 스크롤은 쓰지 않습니다. 텍스트 본문의 안쪽 스크롤도 없앴습니다. 머리글 높이 제한(화면의 45% 또는 본문 200dp 남기기)은 필요 없어져 뺐습니다.
- 두 손가락 확대는 그대로 됩니다. 손가락이 둘 이상 닿으면 WebView가 부모에게 터치를 가로채지 말라고 요청합니다(`PinchWebView`). 이 요청을 빼면 세로로 벌리는 확대가 화면 스크롤에 뺏기는 것을 테스트로 확인했습니다.
- 한계: 확대한 상태에서 세로 이동은 화면 스크롤이, 가로 이동은 WebView가 맡습니다. 확대하는 동안 손가락 아래 지점이 세로로 조금 밀릴 수 있습니다.

확인 범위: 긴 본문이 머리글과 함께 스크롤하는지, 짧은 본문은 스크롤하지 않는지, 세로 확대가 되는지 화면 테스트로 확인했고 에뮬레이터에서 눈으로 봤습니다. 실제 기기에서의 손끝 느낌과 아주 긴 메일의 스크롤 성능은 확인하지 못했습니다.

## 51. 수신 주소를 확인할 수 없다는 문구

## 52. iCloud 계정의 실시간 수신

사용자 요청(2026-11-19)에 따른 것입니다.

- 실시간 수신(IMAP IDLE)은 이미 있었지만 새 계정이 모두 "주기"(약 15분)로 만들어져, 계정 화면에서 직접 바꾸지 않으면 알림이 늦었습니다. iCloud 계정은 처음부터 "실시간"으로 만듭니다. 다른 서비스는 그대로 "주기"입니다.
- 이미 추가한 계정은 바뀌지 않습니다. 설정의 계정 화면에서 동기화 방식을 실시간으로 고르고 저장해야 합니다.
- 실시간 계정도 15분 주기 작업이 함께 확인합니다. 이전에는 실시간 서비스가 꺼져 있으면(기기를 다시 켠 뒤, 시스템이 앱을 끝낸 뒤) 앱을 다시 열 때까지 아무것도 받지 못했습니다. 배터리 최적화 예외를 켜 두면 주기 작업이 앱을 깨울 때 실시간 서비스도 다시 시작할 수 있습니다.
- iCloud가 로그인 뒤에 IDLE을 알려 주는지는 확인하지 못했습니다. 로그인 전 응답에는 없고(2026-11-19 다시 확인), 찾은 자료에도 로그인 뒤 목록이 없었습니다. 알려 주지 않으면 9절대로 5분마다 확인합니다. 실제 결과는 기기 로그(태그 `Dustbird`, "server IDLE support")에 한 줄 남깁니다.
- 만들지 않은 것: 계정 추가 중에 받는 방식 고르기, 기기를 켤 때 서비스 자동 시작, 네트워크가 바뀔 때 바로 다시 연결.

## 53. 폴더블 펼친 화면의 두 칸 배치

사용자 지적(2026-11-19)에 따른 것입니다.

- 폭 840dp 이상이면 메뉴(280dp), 목록(380dp), 메일을 한꺼번에 놓았습니다. 폴더블 펼친 화면(폭 약 930dp)에서는 메일 칸이 270dp쯤밖에 되지 않아 제목이 네 줄로 꺾이고 본문과 버튼이 겹쳤습니다.
- 폭 840dp 이상 1200dp 미만에서는 메뉴와 목록 두 칸만 놓습니다. 메일을 누르면 목록 자리에 메일 화면이 뜨고(뒤로 가기 화살표, 보관, 삭제 포함), 화살표나 시스템 뒤로 가기로 목록에 돌아옵니다. 메뉴에서 다른 폴더를 고르면 메일을 닫고 그 폴더 목록을 보여 줍니다.
- 폭 1200dp 이상(큰 태블릿)은 자리가 충분해 세 칸을 그대로 둡니다. 폭 600dp 이상 840dp 미만은 이전처럼 목록과 메일 두 칸입니다.
- 펼친 화면에서 메일을 읽다가 접으면 같은 메일을 한 칸 화면으로 이어서 보여 줍니다. 접은 화면에서 연 메일은 펼쳐도 한 칸 화면 그대로이고, 뒤로 가면 메뉴와 목록 두 칸이 됩니다.

확인 범위: 폭 1000dp로 강제한 화면 테스트로 메일이 목록 자리에 뜨고 화살표와 시스템 뒤로 가기로 돌아오는 것을 확인했습니다. 에뮬레이터 화면을 폴더블 크기(약 931×702dp)로 바꿔 눈으로 보고, 휴대폰 크기로 되돌렸을 때 같은 메일이 이어지는 것을 확인했습니다. 실제 폴더블 기기에서는 확인하지 못했습니다.

## 54. 알림과 배터리 최적화를 확인하는 팝업

사용자 요청(2026-11-19)에 따른 것입니다.

- 앱이 화면에 돌아올 때마다 시스템 상태를 다시 읽어, 계정 설정이 바라는 것을 시스템이 막고 있으면 팝업으로 알립니다. 한 번에 하나만 보이고 알림이 먼저입니다.
  - 알림: 알림을 켠 계정이 있는데 앱 알림이 꺼져 있을 때. "허용하기"는 시스템 권한 창을 띄우고, 시스템이 더 묻지 않는 상태(두 번 거부한 뒤)와 Android 12에서는 앱의 시스템 알림 설정을 엽니다.
  - 배터리: 실시간 계정이 있는데 배터리 최적화 대상일 때. "허용하기"는 시스템의 허용 창을 바로 띄웁니다(`ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`). 그 창을 쓸 수 없는 기기에서는 배터리 최적화 목록을 엽니다.
- "나중에"를 누르면 앱을 다시 켤 때까지 보이지 않습니다. 실시간을 껐다가 다시 켜면(알림은 계정 알림을 껐다가 다시 켜면) 다시 묻습니다. 계정 알림을 모두 끄거나 실시간 계정이 없으면 묻지 않습니다. 계정을 추가하는 중에는 띄우지 않습니다.
- 받은편지함이 처음 보일 때 시스템 권한 창을 바로 띄우던 것(40절)은 뺐습니다. 팝업에서 이유를 먼저 보여 주고 "허용하기"를 눌렀을 때 시스템 창을 띄웁니다. 창 두 개가 겹치지 않게 하기 위해서입니다.
- 매니페스트에 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 권한을 넣었습니다. 9절에서는 시스템 설정 목록에서 사용자가 직접 찾게 했는데, 삼성 기기에서는 목록에서 앱을 찾는 길이 길어 바로 묻는 창으로 바꿨습니다. 허용 여부는 여전히 시스템 창에서 사용자가 고릅니다. 이 권한은 스토어 정책상 쓸 수 있는 앱이 제한되므로(린트 `BatteryLife`), 스토어에 올리게 되면 다시 판단해야 합니다. 설정 화면의 버튼은 이전처럼 목록을 엽니다.
- 만들지 않은 것: "다시 보지 않기", 삼성의 잠자는 앱 목록 확인(공개된 확인 방법이 없음).

확인 범위: 팝업이 뜨고 사라지는 조건은 화면 테스트 5개로, 권한 창과 설정 화면 중 어디로 보낼지는 단위 테스트로 확인했습니다. 에뮬레이터에서 알림 권한을 끈 뒤 팝업, 시스템 권한 창, 두 번 거부한 뒤의 설정 화면, 실시간으로 저장한 직후의 배터리 팝업, 시스템 허용 창, 허용 뒤 팝업이 사라지는 것을 직접 눌러 봤습니다. 삼성 기기의 시스템 창은 확인하지 못했습니다.

## 55. 팝업 모서리

사용자 지적(2026-11-19)에 따른 것입니다.

## 56. 메일 목록의 로딩 표시

사용자 지적(2026-11-19)에 따른 것입니다.

- 새로 고침 상태 하나로 위쪽 당김 표시와 가운데 로딩 표시를 함께 켜서, 메일이 없는 폴더를 열면 표시가 두 개 돌았습니다. 앱을 켤 때와 폴더를 바꿀 때 앱이 스스로 하는 새로 고침에도 위쪽 표시가 매번 돌았습니다.
- 새로 고침을 "조용히"(앱이 시작)와 "당김"(사용자가 시작)으로 나눕니다. 위쪽 표시는 사용자가 당기거나 메뉴에서 새로 고침을 골랐을 때만 보입니다. 조용한 새로 고침 중에 사용자가 당기면 그때부터 위쪽 표시를 보입니다.
- 가운데 로딩 표시는 보여 줄 메일이 없고 조용히 받아 오는 중일 때만 보입니다. 사용자가 당긴 중에는 위쪽 표시만 보입니다.
- 앱을 켠 직후 화면이 준비되기 전의 가운데 표시는 0.5초 넘게 걸릴 때만 보입니다. 보통은 그 전에 목록이 뜹니다.

## 57. 뒤로 가기 제스처의 화면 전환

사용자 지적(2026-11-19)에 따른 것입니다.

- 내비게이션 라이브러리(navigation-compose 2.10.2)는 뒤로 가기 제스처 중의 전환을 따로 받는데, 지정하지 않으면 나가는 화면을 0.7배로 줄입니다. 버튼으로 뒤로 갈 때의 전환만 지정해 두어서 제스처에서는 화면이 가운데로 줄어들었습니다.
- 제스처 중에는 나가는 화면이 손가락 방향으로 화면 폭만큼 밀려 나가고, 이전 화면이 반대쪽 1/4 지점에서 들어오며 나타납니다. 오른쪽 가장자리에서 시작한 제스처는 방향을 뒤집습니다. 손가락을 따라가도록 이 구간만 일정한 속도(300ms)로 둡니다. 스프링 곡선을 그대로 쓰면 제스처 초반에 화면이 거의 다 빠져나갔습니다.
- 폴더블 펼친 화면에서 목록과 메일이 바뀌는 전환(53절)도 같은 방향의 밀기와 흐려짐으로 맞췄습니다.
- 바꾸지 않은 것: 첫 화면에서 뒤로 가서 앱을 나갈 때 창이 줄어드는 것은 시스템 동작입니다. 아래에서 올라오는 창과 메뉴의 제스처 움직임은 Material 구성 요소의 기본값 그대로입니다.

## 58. 에이전트 연결과 전송 동의

사용자 지적(2026-11-19)에 따른 것입니다.

- 에이전트는 연결과 "메일 내용 전송에 동의"가 둘 다 있어야 일합니다. ChatGPT로 로그인만 하고 동의를 켜지 않으면 "에이전트와 쓰기" 창과 에이전트 화면이 "연결되어 있지 않습니다"라고만 안내해서, 연결했는데도 연결이 안 된 것처럼 보였습니다.
- 연결은 되어 있고 동의만 빠진 경우를 따로 보여 줍니다. 무엇이 전송되는지 설명과 "메일 내용 전송에 동의" 체크박스, "동의하고 계속" 버튼이 있는 카드가 그 자리에 뜨고, 동의하면 바로 쓸 수 있습니다. 쓰기 창과 에이전트 화면이 같은 카드를 씁니다.
- 동의를 자동으로 켜지는 않습니다. 메일 내용이 밖으로 나가는 일이라 사용자가 직접 고르게 둡니다.
- 하지 않은 것: 계정 추가의 "문장으로 입력하기"는 이전처럼 에이전트 설정으로 안내합니다.

## 59. 계정을 추가할 때 이름표 정하기

사용자 지적(2026-11-19)에 따른 것입니다.

- 메일 목록의 계정 알약과 "받은 주소" 알약에 들어가는 글자를 어디서 정하는지 알기 어려웠습니다. 계정 알약은 "짧은 이름"이라는 칸에서 정했고, 받은 주소 알약은 주소의 @ 앞부분으로 자동으로 정해져 계정을 추가한 뒤에야 바꿀 수 있었습니다.
- 계정 추가 양식에 "메일 목록에 붙는 이름표" 구역을 두었습니다. 맨 위에 메일 목록과 같은 알약으로 미리보기를 보여 주고, 입력하는 대로 바뀝니다. 계정 색도 실제로 쓰일 순서의 색입니다.
- "짧은 이름"은 "계정 이름표"로 이름을 바꾸고 "개인, 업무, 학교" 빠른 선택을 붙였습니다. "받은 주소 이름표"를 새로 넣었고, 비워 두면 이전처럼 주소의 @ 앞부분을 씁니다. 이미 쓰는 이름표와 겹치면 저장할 때 알려 줍니다.
