# 서비스 프로필별 확인된 동작과 미확인 동작

구분은 네 가지입니다.

- 공식 문서 확인: 서비스 공식 도움말에서 직접 읽은 내용
- 로그인 전 응답 확인: `openssl s_client`로 서버에 접속해 로그인 전에 받은 CAPABILITY와 EHLO 응답. 로그인 후의 동작은 알 수 없습니다.
- 이전 클라이언트에서 확인: iCloud 계정 하나가 기존 서버의 메일 클라이언트에서 실제 수발신된 사실(이 앱에서 확인한 것은 아닙니다)
- 미확인: 위 어디에서도 확인하지 못한 것. 사실로 단정하지 않고 실제 계정으로 점검합니다.

로그인 없이 앱의 연결 설정(`SessionConfig`)으로 실제 서버 8곳에 접속한 점검도 했습니다. 수신 imap.mail.me.com, imap.gmail.com, imap.naver.com(993 TLS)과 발신 smtp.mail.me.com:587(STARTTLS), smtp.gmail.com:465(TLS)와 587(STARTTLS), smtp.naver.com:587(STARTTLS)과 465(TLS)가 모두 TLS 협상과 서버 이름 검증까지 통과했습니다. 암호는 보내지 않았고 로그인 시도도 하지 않았습니다. JVM 기본 신뢰 저장소 기준이므로 안드로이드 기기의 신뢰 저장소에서는 따로 확인되지 않았습니다.

이 앱 자체의 실제 계정 검증은 한 번도 수행하지 않았습니다. 검증 절차는 `docs/verification-checklist.md`에 있습니다.

## iCloud 메일

| 항목 | 값 | 근거 |
| --- | --- | --- |
| 수신 | imap.mail.me.com, 993, TLS | 공식 문서 확인, 이전 클라이언트에서 확인 |
| 발신 | smtp.mail.me.com, 587, STARTTLS | 공식 문서 확인, 로그인 전 응답 확인 |

| 로그인 전 수신 기능 | IMAP4rev1, SASL-IR, AUTH=PLAIN/XOAUTH2 등, XAPPLEPUSHSERVICE | 로그인 전 응답 확인. IDLE, SPECIAL-USE, UIDPLUS는 로그인 전 목록에 없음 |
| 로그인 전 발신 기능 | 크기 28319744, SMTPUTF8, 8BITMIME, CHUNKING, AUTH LOGIN PLAIN XOAUTH2 등. 인증서 검증 통과, TLS 1.3 | 로그인 전 응답 확인 |
| 보낸 편지함 자동 저장 | 프로필은 "저장하지 않음"으로 둠 | 미확인. 어느 쪽이든 Message-ID를 먼저 검색하므로 중복은 생기지 않음 |
| 폴더 속성 제공, IDLE 지원, 동시 연결 한도, 하루 발송 한도, 등록되지 않은 발신 주소 처리 | - | 미확인 |

## Gmail

| 항목 | 값 | 근거 |
| --- | --- | --- |
| 수신 | imap.gmail.com, 993, TLS | 공식 문서 확인(서버 이름은 이전 조사 자료와 일치), 로그인 전 응답 확인 |
| 발신 | smtp.gmail.com, 프로필 기본 465 TLS (587 STARTTLS도 응답함) | 공식 문서 확인, 로그인 전 응답 확인 |
| 인증 | 앱 비밀번호. Google은 앱 비밀번호를 권장하지 않으며 회사, 학교, 보안 키만 쓰는 2단계 인증, 고급 보호 계정에서는 발급할 수 없음 | 공식 문서 확인 |
| IMAP 사용 설정 | 개인 계정은 2025년 1월부터 항상 켜져 있음. 조직 계정은 관리자 정책 | 공식 문서 확인 |
| 동시 접속 | 계정당 클라이언트 15개 | 공식 문서 확인 |
| 폴더 크기 제한 옵션 | Gmail 웹 설정에 폴더당 메일 수 제한이 있음 | 공식 문서 확인 |
| 로그인 전 수신 기능 | IDLE, UNSELECT, NAMESPACE, QUOTA, ID, XLIST, CHILDREN, X-GM-EXT-1, SASL-IR, AUTH=XOAUTH2/PLAIN/OAUTHBEARER | 로그인 전 응답 확인 |
| 로그인 전 발신 기능 | 크기 35882577, SMTPUTF8, CHUNKING, 한 번에 수신자 100명(RCPTMAX), 메일 1000통(MAILMAX) 한도 표시 | 로그인 전 응답 확인 |
| 보낸 편지함 자동 저장 | 프로필은 "저장함"으로 둠 | 알려진 동작이지만 이 앱에서는 미확인. 발송 후 보낸 편지함을 검색해서 확인하고 없으면 저장 실패로 표시 |
| 여러 폴더에 동시에 보이는 구조(라벨과 전체보관함) | 프로필에 표시 | 알려진 동작. 목록은 같은 Message-ID를 한 번만 보여 주고 전체보관함은 동기화하지 않음 |
| 토큰 인증(OAuth) | 서버는 지원함. 이 앱은 구현하지 않음 | 로그인 전 응답 확인. 필요한 준비와 근거는 README의 후속 작업 참고 |

## 네이버 메일

| 수신 | imap.naver.com, 993, SSL/TLS | 공식 문서 확인(고객센터 21344, 21349) |
| 발신 | smtp.naver.com, 587, TLS(프로필은 STARTTLS) | 공식 문서는 587만 안내. 로그인 전 응답에서는 587 STARTTLS와 465 TLS가 모두 응답함. 공식 문서에 없는 465는 사용하지 않음 |
| 사용자 이름 | 네이버 메일 주소 전체 | 공식 문서의 Thunderbird와 Mac 메일 안내. "아이디만" 쓰는 안내는 공식 문서에서 찾지 못함 |

## 직접 설정

서버 이름, 포트, 보안 방식(TLS 또는 STARTTLS만), 사용자 이름을 모두 입력받습니다. 암호화 없는 연결은 선택지가 없습니다.
